## 1. `ingress_pressure`：追赶延迟曾被当成接收缺口锁存

代码确认的链路：worker 取出一帧时，只要排队超过 1 秒，就设置 `delivery_gap=True`。备份即使随后已经追上，只要 FIFO 持续有消息、没有触发 0.2 秒的 Empty 超时，该标记仍可能保留；就绪判定又会否决这个标记。它将“处理稍晚但 FIFO 完整”混同于“实际丢帧”，热门流尤其难靠 Empty 清除。

本轮移除“仅因排队延迟而设置 delivery gap”的路径。仍要求：

- 当前所需资产有完整快照、有效交易所时间，当前订阅完成；
- 当前排队延迟不超过 1 秒，正在处理的帧没有超过新鲜度门槛；
- 连接、代次有效，没有 overflow / resync / invalid 或当前资产待恢复；
- 恢复缺失的实时盘口时，影子水位不能低于已发布的时间水位。

真正的溢出仍推进 epoch、废弃不完整影子盘口并补全量快照；断连仍使连接不可用。没有提高上述延迟门槛。回归专门构造“先处理一帧 1.2 秒前的消息，随后 FIFO 持续非空”，验证追上后可以恢复就绪，且不需要 REST 或 Empty 超时。

这不是说所有压力都误判：81 个采样的主路 `Q` 字段里，接收队列深度最高 **5629**。因此真实积压仍应否决接管。旧日志没有完整的备份队列状态，不能把 85 次未就绪 `ingress_pressure` 全部归因于锁存问题。本轮给 B/R 补齐相同的队列、恢复和预热诊断字段，便于区分。

## 2. 每五分钟整批重建：到期清空目录触发了双备份退役

监督循环会在到期时立即移除旧场次；发现循环通常稍后才拿到新场次。中间分片没有热门资产，旧 `_apply_assignment` 因 `not assets / not hot_shard` 将 B、R 一起退役。下一次发现新场次后，才重新准备两条备份。这个代码路径与日志中约 289–293 秒成批 `redundant prepare`、15 分钟边界四组一起重建吻合。

本轮采用以下行为：

1. 从**同一次公开 Gamma 发现响应**另外收集所选热门系列最近的下一场次。评估目录的数量、每系列上限及 lookahead 选择规则保留；预热目录独立，不提前进入 Pipeline、纸面评估或成交记录。没有新增定时 REST 行情轮询。
2. 距下一场次开始 **90 秒内**，在已有 B/R 上动态预订下一对资产。每系列最多保留最近一个下一场次；仍使用共享订阅节流器。主路不额外订阅这个预热目录，不增加物理备份连接数。
3. “当前所需资产”和“预热资产”分开判定。下一场次订阅尚在等待或缺快照，不会使当前已完整的备份失去就绪；诊断阶段此时仍显示 `ready`，并另报 `pending_current`、`prewarm_assets`。
4. 到达已知下一场次的开始时间时，监督循环可直接激活它，复用已有连接和影子全量盘口。旧资产退订，影子盘口和水位同步裁剪。已有快照可在市场静默时发布，不必再等下一笔成交。
5. 若没有发现下一场次，空备份最多保留 **90 秒**等待目录恢复；不把空连接/旧场次盘口算作就绪。超时才退役，防止无限保留无用连接。

四组分别测试了跨边界保持两条备份、下一场次不提前进入评估、两条连接身份不变。另覆盖只有一条预热拿全快照时仍有一条就绪备份，以及缺目录时保留连接、恢复订阅、最终超时退役。

主路在预热期间故障时，提升后的主路只保留当前所需资产；未发送的预热订阅被移出队列，已经发送的多余订阅会退订。REST / 监督循环可修复盘口和更新就绪，但**只有该连接自己的 worker 可以提升备份**，避免其已经取出、尚未处理的帧在提升时被遗失。新增阻塞 worker 的回归验证此屏障。

## 4. 降低三路重复解析和指纹序列化

新增观察器管理器内共享的短时解析缓存：最多 **512 帧、1 MiB 计费原文预算、2 秒 TTL**；文本按每字符 4 字节保守计费，超大帧直接旁路。这个预算是缓存原文计费，**不是解码对象的 RSS 上限**。空闲时同样过期清理。

相同原文在三路 worker 中只解析一次；缓存公开事件只读共享，指纹保存在对象属性中，不进入消息字段。全量 book、增量行的规范化指纹可复用，减少 JSON 重复序列化。每路接收帧/字节计数仍独立；同源完全相同的多笔成交仍按重数保留，跨来源副本去重，旧快照/旧价位仍受水位保护。

## 5. 03:39 迁移的 18.4 秒：静默跨度，不是已证实的迁移断流

原始日志（UTC 加 8 小时即 SGT）：03:39:06 prepare，03:39:10 commit。最大两条 `reassignment/unverified` 对应的资产前缀为 `323382201900`、`256593106749`：

- 原路末次交易所时间都是 **03:38:52.205**，提交时距末次接收约 **18375.520 / 18376.413 ms**。
- 同一次提交在约 **5–6 ms** 后记录 `snapshot_restored`；目标影子快照的交易所时间仍为 **03:38:52.205**，交易所水位差 **0 ms**。
- 恢复记录用影子原始接收时间计算的跨度约 **14750.806 ms**。这表明目标快照早于提交就已收到；该数字也不是提交后等待了 14.75 秒。

因此现有证据更符合“市场静默 + 新全量快照与原路末次事件没有相同指纹”。已有迁移逻辑在完整且追上水位的目标盘口准备好之前，不切断原订阅，并在提交锁内保留/替换盘口。不能将这 18.4 秒直接当作迁移导致的盘口不可用时间。公开源没有序列号，这些证据仍不能证明静默期间逐笔历史成交绝无遗漏。

本轮保留 `unverified` 的保守语义，补充：`source_silence_ms`、`destination_silence_ms`、`destination_exchange_gap_ms`、`market_silence_compatible`、`book_preserved`、`book_unavailable_ms`、`historical_trades_verified`。只有已准备盘口且目标连续性水位追上时，才报告 `book_preserved=true / book_unavailable_ms=0`；旧目标不能据此宣称无缺口。原 `receipt_gap_ms` 兼容保留，不能再单独作为丢包证据。

## 6. 新增指标与口径

| 字段 | 口径 |
| --- | --- |
| `ws_hot_backup_by_group[group].zero_ready_backup_seconds` | 该热门组就绪备份数为 0 的累计秒数，按状态转移和监督 tick 积分；独立于主路是否健康 |

| `zero_ready_backup_active` | 该组在本管理器会话曾出现，开始累计；换期时暂时没有目录也继续累计，避免隐藏发现缺口；进程重启后重置 |
| `ws_process_rss_bytes` | Linux `/proc/self/statm` 当前 resident pages × 页大小；不是 lifetime peak，平台不支持则 null |
| `ws_retiring_connections` | 尚需等待 reader / worker 结束的退役连接数量 |
| `ws_parsed_frames` | 缓存条目、计费原文大小、命中及未命中次数 |
| `ws_backups / ws_reserves` | 同口径报告 ready、阶段、当前订阅待发数、预热资产数、队列深度/容量/高水位、排队时间、drops、delivery gap、resync、影子水位资产/价位数及连接年龄 |
| `ws_merge_metrics` | 保留条目/去重/旧数据计数，增加资产和价位水位数量 |

## 风险与部署后观察

本轮未部署，没有新的生产验收数据，不承诺任何网络/上游故障下始终至少一条备份就绪，也不宣称 RSS 或 CPU 已在生产下降。

1. 连续跨过多个 5m、15m 边界，检查 B/R 连接年龄是否持续增长，`redundant prepare` 是否不再随每次正常换期成批出现。四组目标仍为 2，至少一条覆盖应在预热快照成功时跨边界保持。
2. 分组观察 `zero_ready_backup_seconds` 的增速和 before / after / steady 分段。特别查换期后 45 秒内的增长；目录为空时新累计仍应增长。主路故障同时核对 ready 备份条数、`takeover_gap_ms` 和实际恢复方法。
3. 预热会在最多 90 秒窗口内临时增加备份的订阅资产，单系列通常从 2 变为 4；同片其他资产仍保留。未来市场也可能活跃，带宽/CPU 可能增加。若发现接口未提供下一场次、订阅被真实压力阻挡或两份快照都不全，仍会出现零覆盖，空连接保留并不能制造可用盘口。
4. 对照 B/R 的 queue depth / wait、delivery gap / resync / drops 解释 `ingress_pressure`。不能靠放宽阈值制造 ready；期望追赶后不再锁存旧延迟，同时真实积压继续可见。注意冷门 update_silence p95、1008、1013、REST 限流/失败数是否恶化。
5. 用新增 RSS 跟踪跨至少多轮换期后的基线和峰值，并同步记录队列深度、去重 entries、资产/价位水位数、解析缓存预算和退役连接数。旧资产水位应回落到当前+下一场次范围，缓存不应超上限；如果对象数量稳定而 RSS 继续增大，需要进一步堆/分配器证据，不能用本轮测试代替生产泄漏定位。Docker memory 与进程 RSS 口径不同。
6. 相同消息速率下比较 CPU、缓存命中率与恢复排队。微基准收益不能替代容器观测；额外预热流量可能抵消部分解析收益。
7. 迁移出现大 `receipt_gap_ms` 时，同时检查两端 silence、exchange gap、`book_preserved` 与盘口缺失。`market_silence_compatible` 只表示证据相容，仍不代表逐笔成交已经验证完整；REST 和影子快照也不能补回缺失历史成交。
