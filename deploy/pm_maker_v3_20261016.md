## 行为（对应文档章节）

**公允价与毒性（§5）**：`parse_rules` 只看市场的 `resolutionSource` / 规则文本：Chainlink 数据流为 w=60，币安 K 线为 w=0，含 "50-50" 时平局按 0.5；解析不出就不建行、不报价。F = Φ(μ_D/√V_D)，V_D 用闭式解（单测与数值积分误差 < 1e-9）。开盘价窗口开始前 F 恒为 0.5、Z = 0，与现货无关。保守公允价：fair_Up = min(F, M)，fair_Down = min(1−F, 1−M)，M 为 Up 一档微价；|F−M| > `gap_max`（4¢）或 Z > `z_hard_max` 时转只减仓（可回退）。

**阶段机（§7）**：WAIT → PREOPEN → STRIKE → OPEN ⇄ REDUCE → HEDGE → FLAT → 结算，阈值按周期配置（`phases`、`preopen_windows`、`preopen_pull_s`、`strike_wait_s`）。只有 PREOPEN/OPEN 开新仓，STRIKE/REDUCE/HEDGE 只挂对冲侧，FLAT 全撤。数据过期、Up/Down 时间差、交叉盘、整币种跳价时，任何阶段都临时转入平静期并全撤。

**报价（§7）**：bid = floor_tick(fair − h + 0.2 tick)，h = max(h_min, k_tox·Z − λ·fee(fair) + c0) + 库存偏斜 + 成交流/自成交/动量/软止损加宽（只加宽、只对开仓侧）。对冲侧下限为 max(0, k_hedge·Z − λ·fee)，HEDGE 阶段放宽到 −e_neg。开仓侧只加入或改善最优买价（最多 1 tick），post-only，fair 不在 [0.10, 0.90] 或价差超过 cell 近 1 小时中位数 2 倍时不开仓；对冲侧最多落后最优买价 3 tick。零库存时两边 bid 之和 ≤ 1 − 2·h_min（单测随机断言）。

**数量**：开仓侧 min(10 × 系数, N_cap − |n|, 风控余量, 资金)，系数取观察期/软止损/自成交后 0.5 的最小值；对冲侧 |n| 永不受上限约束，只在允许开仓时才 max(|n|, 10) 反向超挂（反向不超过 N_cap）；单笔 ≤ 25 股。

**OMS（§7 撤改单 8 条）**：目标消失即撤；目标价下降立即撤并重挂；上调需持续 300 ms 且已停留 500 ms；目标量 < 现挂一半或超出风控余量则撤后重挂，需加量时同价追加新单保留原单队列；公允价不利移动 ≥ 0.5×(fair−bid) 撤单；同侧一档深度在窗口内无成交下降 ≥ 50% 撤单并冷却 2 s；币安单次收益 > 4σ 时整币种全撤冷却 3 s，并等待晚于跳价的新盘口。每市场每秒最多 5 次动作，保护性撤单不受限。

**成交模拟（§8）**：挂单在决策后 250 ms 才进入队列；撤单在决策后 250 ms 生效，生效前的成交照算；按交易所时间判定。挂入时 queue_ahead = 该价显示量（我方同价旧单也排在前面），同价成交先消耗 queue_ahead；价位低于可见深度时同价成交不算（未知队列）；出现低于我方价的卖出成交，剩余量按我方价全部成交。别人撤单默认不前移队列，"按比例前移" 只作对照统计（`prop_filled`）。互补成交默认 `verify`：只统计同一 transaction_hash 在两个 token 上的形态（`complementary_checked/sum_one`），不计成交；`count` 模式下按 tx 去重计入。镜像盘口只做一致性统计。Up+Down 立即合并兑 1；结算 0/1，平局 0.5；无结果且有库存时一直等待，绝不推断。重启时残留的挂单视作"可成交、待撤单生效"，停机时按延迟撤单。

**风控（§10）**：单市场 |n| ≤ 20、最坏损失 ≤ $12、锁定资金 ≤ $100；单币种同方向 ≤ 60 股；全局同方向 ≤ 100 股、最坏损失 ≤ $75、锁定 ≤ $1000。所有上限按"每张挂单都成交"的最坏情况预留，撤单生效前仍计入，且在挂单时按本轮已挂订单复核；只约束风险侧，对冲侧始终允许。当日盈亏（已实现 + 按保守公允价的未实现）≤ −$50 软止损（数量减半、+1 tick），≤ −$100 或账户 2% 止损触发时只对冲；组合当日 ≤ −$25 或当日 AS60 低于近 7 天均值 2σ 时该组合当日停开新仓，并在下次日评中退出、冷却 3 天；滚动 7 天 ≤ −$200 时锁存 `state.maker.halt`，只对冲，需人工复盘后清除。

**选市（§6）**：全宇宙 20 个组合都跑影子多档（目标价 −1/0/+1/+2/+3 tick，零资金，独立排队，同样的延迟），记录 τ/Z/队列分桶与 1/5/15/60/300 s markout。每个市场结算时写 `market_summary` 和 `shadow_fills` 事件（`qd_polymarket_maker_events`）。每天 UTC 00:05 用前 7 天（半衰期 3 天）已结算市场重新评分：评分样本为"实盘可挂"的目标档影子成交的每市场盈亏（不含返佣），按市场聚类自助抽样 2000 次，取 90% 单侧下界。准入：LCB > 0、≥ 150 个有成交市场、≥ 1000 股、AS60/成交优势 ≤ 0.7，且通过流动性、价差、数据质量、可报时间占比四个硬过滤；按均值/标准差排序，最多 6 个、同币种最多 3 个；新准入观察期 3 天减半。退出：连续两次 LCB < 0，或近 3 天均值 < 0 且 ≥ 50 个市场，或触发组合熔断；退出后冷却 3 天。样本不足时用冷启动先验：BTC/ETH 1h、BTC/ETH 15m、BTC/ETH 5m（仅开盘前），按观察期规模运行。

**评估（§11）**：每笔成交 q(Y−p) = 成交优势 q(M⁻−p) + 逆选 q(M_h−M⁻) + 持仓残差 q(Y−M_h)，单测断言三项之和等于总盈亏、且等于账本净盈亏。日报含每市场净盈亏、每股成交优势/AS_h/残差、AS60/优势比、中和率、库存半衰期、按改善/加入分开的每挂单小时成交、平均锁定资金与资金收益率/周转率、平静期未配对股数与单边结算盈亏、Brier 与十分位可靠性、队列模型敏感度、跳过原因与阶段分布、熔断告警、当前选市名单。

## 与文档的差异（数据层约束，均可配置）

| 项 | 文档 | 本实现 | 原因 |
| --- | --- | --- | --- |
| 结算源价格 | PolyBolt Chainlink + 币安 WS | 默认币安 REST 参考价（observer 每 5 s）；可开 `POLYMARKET_OBSERVER_SPOT_WS_ENABLED` 用币安现货 WebSocket（见 `pm_spot_ws_20261016.md`）。K 与 X 同源计算，基差相减抵消；1h/1d 优先用 priceToBeat | PolyBolt 需凭证（要钱包），不接 |
| 现货过期 `spot_stale_ms` | 1000 | 默认 6000，开启 WebSocket 现货后建议改回 1000；Z 的有效延迟 = `latency_eff_s` + 现货年龄 | REST 5 s 一次时开盘后短周期基本不可报 |
| 短周期盘口过期 `book_stale_ms_short` | 1000 | 2000 | 录制仅在 top5 变化时、每 token ≥ 1 s 写一行 |
| 深度骤降窗口 `depth_pull_window_ms` | 500 | 1500 | 同上，500 ms 内不会有两张快照 |
| σ | 1 s 收益、季节性、每周 MLE | 5 s 采样双 EWMA，季节性=1，`vol_scale` 手动；σ_short 不低于混合 σ | 无 1 s 数据；校准流程未自动化 |
| 录制范围 | 全部 20 个组合 | 默认仍只有 BTC/ETH 5m/15m；现已可配置到任意币种/周期（见 `pm_recording_scope_20261016.md`） | 未录制的组合因无盘口处于平静期 |
| 未实现 | 永续领先、宏观日历、撮合引擎重启/post-only 窗口、时钟偏差、+200 ms 敏感度、周度网格校准、离线回放引擎 | 宏观事件用 `event_times` 手工配置；其余未做 | 需新数据源或离线工具 |

按文档伪代码，对冲侧半价差为 max(下限, base − 库存偏斜)，HEDGE 阶段只是放宽下限。5m 开盘后 Z 很高，对冲价常落后最优买价超过 3 tick 而不挂，开盘前的成交大多会持有到结算；这与文档"5m 只做开盘前"的结论一致，已写成单测。

## 追加（2026-10-16）：1d 结算打印时点与官方结果等待

基于 `claude/magical-austin-a97023` `cbd2225`（录制范围 + `maker_model.print_lag`）。仍只做纸面：不接钱包、不下单、不碰 `PAPER_AUTO`。

**1d 规格改用打印时点。** `parse_rules` 遇到币安 "1 minute candle" 规则时返回 t0 = eventStartTime + 60 s、t1 = endDate + 60 s，并带 `lag=60`；1h（1H K 线开/收）和 Chainlink 5m/15m/4h 的 `lag=0`，t0/t1 仍是边界，行为不变。

选择直接平移 t0/t1，而不是另加一个打印时间字段。用到 t0/t1 的地方（g(t)、V_D、阶段、开盘价读取、成交截止、markout 截止、结算闸门、`settle_timeout_s`）都应该跟着打印时点走，平移后不用逐处判断。依据：只读查了 Polymarket data-api，BTC 1d 市场在 endDate 16:00 UTC 之后仍有成交（10/15 有 16:01、16:07、16:08、16:10 的成交，10/14 有 16:10 的成交），盘口一直交易到结算（closedTime 16:12–16:13）。所以 endDate 到收盘打印之间的那 1 分钟仍有真实价格风险，并不是休市。

- 开盘：边界之后、开盘价打印之前（美东 12:00–12:01），K 和 X 随现货同步变化，F = 0.5，Z = 0，阶段为 PREOPEN；打印前 5 s 进入 STRIKE，打印后 2 s 进入 OPEN。原来边界后 2 s 就进入 OPEN，开盘价锁的是早 1 分钟的价格。
- 开盘价（没有 priceToBeat 时）：收盘价规则优先取打印时点之前最后一个观测，和代理结算的取价方向一致；1h 开盘价仍取 T0 及之后的第一个观测。
- V_D 计入 endDate 之后的 60 s。例如 endDate 前 100 s，V 由 100σ² 变为 160σ²。
- REDUCE/HEDGE/FLAT 都按距打印时点计，比原来晚 60 s。FLAT 恰好从 endDate 开始，也就是在打印前 60 s 撤光所有挂单。
- 成交截止、markout 截止、结算闸门和 `settle_timeout_s` 都从收盘打印起算。
- 兼容：v3 还没部署。本提交之前已创建的 v3 行沿用存储的旧规格（无 `lag`），会按旧逻辑跑到结算。

**等官方结果，再回退代理。** 新增 `official_wait_binance_s`（默认 1800）和 `official_wait_chainlink_s`（默认 300），按 `spec.source` 选用（legacy 规格按币安处理），两者都不能超过 `settle_timeout_s`（否则配置无效）。`RecordedFeed.outcome` 只要 `windows.official_outcome` 有值就立即使用（`estimated=False`）；没有值时，从最终打印起等满上述时长才用币安样本代理（`estimated=True`）。设为 0 即恢复原行为：打印后第一次轮询就用代理。

- 默认值的依据：1h/1d 通过 UMA 结算，官方结果在 end 后 11–18 分钟出来；observer 每 60 s 轮询一次 Gamma（每次 10 个窗口），还要再加 1–2 分钟，30 分钟留有余量。Chainlink 组合（含 4h）大约 1 分钟自动结算；而代理是拿币安点价去对 Chainlink 60 s TWAP，误差最大，所以也等 5 分钟。
- 等待期间：市场处于 FLAT，没有挂单；库存仍计入风控上限，未实现盈亏按最后一次保守公允价计，和实盘一样，资金在结算前一直被占用。结算盈亏记在实际结算的那一天。打印之后的轮询不再计入 `phase_counts`，避免等待期把阶段分布里的 FLAT 撑大（250 ms 轮询一次，等 15 分钟约 3600 次）。
- 未做：回退到代理后，即使官方结果迟到且与代理不同，也不会回改账本（这类结算仍计入 `estimated_settlements`）。
