# Polymarket 纸面做市 v3 调参（录制回放校准）— 2026-10-16

分支 `claude/quantdinger-v3-tuning-97adca`，基于 `main` `9daa4c1`（含 PR #65 v3、PR #66 observer）。
只做纸面：不接钱包、不签名、不下真实订单、不碰 `PAPER_AUTO`，吃单保持关闭。风控上限（`N_CAP`、`WORST_LOSS_*`、`LOCK_*`、`*_STOP`、`N_CAP_*_DIR`）一个都没改。未合并、未部署。

## 1. 线上现象与根因

部署后 15 分钟（SGT 10:57–11:12）只挂 1 单、0 成交。用回放（见第 3 节）在同一份录制数据上跑部署时的代码，45 小时只成交 10 股，复现了线上情况。原因有四层，前两层是数据判定问题，后两层是报价规则问题：

| # | 原因 | 证据（15m，可开仓时段） | 处理 |
| --- | --- | --- | --- |
| 1 | **安静盘口被当成过期。** 录制器只在前 5 档变化时写行，盘口 10–60 s 不变很常见；maker 要求最新行 ≤ 2 s，否则转平静期并全撤。 | 原代码回放 book_stale 占 20%。判为过期时，录制器 0.5 s 内仍在写其他行（通道活着），盘口年龄分布在 2 s–60 s。 | 录制器存活（任意盘口行 ≤ `FEED_STALE_MS`=2 s）时，盘口在 `BOOK_QUIET_MS`=60 s 内仍算有效；写入线程落后时自动回到 2 s 严格判定。修复后 1.5%。 |
| 2 | **Up/Down 时间差误判。** 两个 token 分别节流写入，时间戳常差 >250 ms。 | 同一时间戳写入的 5,842 对盘口中 5,831 对完全镜像（Up 买价 p = Down 卖价 1−p，数量相同）；时间不同的对子里约一半顶部不一致，即旧的那边漏了更新。 | 顶部互为镜像就视为一致；顶部不一致且时间差超限时，用较新一边的镜像重建另一边（一边缺失时同样处理），计入 `mirror_rebuilt`。 |
| 3 | **开盘价窗口丢失（strike_unknown）。** 开盘价积分只在盘口正常的轮询里计算，而现货样本只保留 3 分钟；T0 附近盘口缺失/过期，整场市场就再也算不出开盘价。线上 ETH:15m 当时就处于这个状态。 | — | 每次轮询先锁定开盘价（`Maker.strike`），与盘口状态无关。 |
| 4 | **报价规则使双边挂单几乎不可能。** ① 保守公允价 fair_Up=min(F,M)、fair_Down=min(1−F,1−M)，两边之和只有 1−\|F−M\|，而 \|F−M\| 中位数约 3¢；② 开仓侧只能加入/改善最优买价，盘口顶部挂量常严重不平衡，微价 M 贴近一边，另一边的报价必然落后；③ `GAP_MAX`=4¢ 让 37–44% 的可开仓时间处于只减仓；④ `K_TOX`=3 时 h≈3Z−1.75¢，Z 常在 0.02–0.03，报价离最优价 4 格以上。 | 即使 k_tox=0、闸门全关，双边同时在挂也只有约 1%。 | 见第 2 节参数。 |

另外两个与参数无关、只能靠 observer 配置解决的因素（本 PR 不改 observer）：

- 线上 `POLYMARKET_OBSERVER_UPDOWN_LOOKAHEAD_SECONDS=0`、`UPDOWN_PER_PAIR_LIMIT=1`：下一场市场开盘后才被发现，首个盘口中位数晚到 31 s（p90 57 s，前 6 小时样本），并且**开盘前（PREOPEN）永远没有盘口**，所以冷启动里的 `BTC:5m:preopen`、`ETH:5m:preopen` 在线上实际不会挂单。
- 参考价是 5 s 一次的币安 REST，Z 的有效延迟 = 0.3 s + 现货年龄（平均约 2.6 s），5m 开盘后 Z 大多在 0.03–0.1。

## 2. 参数改动（风控上限不变）

| 参数 | 原值 | 新值 | 依据（回放，45 h，BTC/ETH 15m） |
| --- | --- | --- | --- |
| `GAP_MAX` | .04 | **.06** | 下单时 \|F−M\|>6¢ 的成交在三组参数下都明显亏损（每股 −4.6¢ 到 −23¢），≤6¢ 各档基本持平；见 4.2。 |
| `Z_HARD_MAX` | .03 | .03（不变） | Z>0.03 的成交 60 s 期望约 −4.2¢/股，≤0.03 为 −0.2¢ 到 −2.4¢；放宽到 .045 成交多 25% 但期望变差。 |
| `FAIR_TOL`（新增） | — | **.03** | fair_Up=min(M, F+tol)、fair_Down=min(1−M, 1−F+tol)；tol=0 即原 min(F,M)。\|F−M\|≤4¢ 时模型与盘口 Brier 相同，6–16¢ 时盘口更准（见 4.1），所以模型只在偏离超过自身噪声（约中位数 3¢）时才压低一侧。 |
| `K_TOX` | 3 | **1** | k=3 时报价远离最优价，45 h 仅 17 股/时成交且 60 s 期望 −3.2¢（只剩被扫穿的成交）；k=1 期望约 −1.2¢，k=1.5 约 −1.3¢ 但成交少一半。 |
| `OPEN_MAX_BEHIND_TICKS`（新增） | 0（只加入/改善） | **3** | 开仓侧按 fair−h 挂，可落后最优买价至多 3 格（价位在录制深度内才有排队数；否则只认扫穿成交）。0 时正常时段双边在挂 ≤2%。 |
| `DEPTH_PULL_FRAC` | .5 | **1** | 正常时段单边缺失的头号原因是深度骤降守卫后的冷却（约 40%）。改成"该价位整档消失且无成交才撤"。频繁撤单会丢掉排队位置，重挂后只剩被扫穿时才成交：同参数下 60 s 期望由 −2.7¢ 改善到 −1.2¢/股。 |
| `DEPTH_PULL_COOLDOWN_MS` | 2000 | **500** | 同上。 |
| `BOOK_QUIET_MS` / `FEED_STALE_MS`（新增） | — | 60000 / 2000 | 见第 1 节 #1。线上写入延迟实测 0.17 s。 |
| `COLD_START` | BTC/ETH 1h、15m、5m:preopen | **BTC:15m,ETH:15m,BTC:5m:preopen,ETH:5m:preopen** | 1h 没有录制（observer 默认只录 5m/15m），见第 6 节。5m 开盘后在所有参数下 BTC 都亏（45 h −$50 到 −$80），保持只做开盘前。 |

`H_MIN`（.01）、`LAM_FEE`、`K_HEDGE`、风控、模拟器参数都不变。原 v3 参数表仍可通过环境变量完全恢复（`FAIR_TOL=0`、`OPEN_MAX_BEHIND_TICKS=0` 等），单测里用 `DOC` 固定原表验证原机制。

## 3. 回放方法

- **数据**：从新加坡服务器只读导出（`default_transaction_read_only=on`，分 6 小时块、服务器端 `nice -n 19` 压缩），SGT 10/14 14:39 – 10/16 11:23 共约 45 小时：books 172.9 万行、trades 92.2 万行、BTC/ETH 5m/15m 窗口 1,436 个（含官方结果）。未写库、未重启、未改配置。
- **参考价**：录制样本只在有在册市场时写入，5m 与 15m 同时换期（:00/:15/:30/:45）时有几十秒空档，而线上 maker 用的是连续轮询的 REST 价。所以用币安公开 1 s K 线按 5.16 s 节奏重建 REST 轮询；与录制的 REST 价对比平均差 0.1 bp（BTC）/ 0.2 bp（ETH）。
- **回放器**：`app/services/polymarket/maker_replay.py`，直接驱动真实的 `Maker`，每 250 ms 一次轮询，喂"截至当时已收到"的最新盘口、币安价和新成交，按官方结果结算。成交模型就是线上的悲观排队；另跑"别人撤单按比例前移队列"作敏感性对照。命令：`python -m app.commands.polymarket_maker_replay --data DIR [--set key=value ...]`。
- **口径**：
  - 可开仓时段 = 时间阶段为 OPEN 且市场已在册（有过盘口）。
  - 正常时段 = 其中数据正常、未被价差/Z/风控闸门拦截、两侧公允价都在 [0.10, 0.90]、无价差突变、库存为零的轮询。
  - 期望 ev60 = 成交优势 + 60 s 逆选（每股，不含结算残差）。

## 5. 预期挂单率与成交率（新默认值，冷启动半仓 5 股，BTC/ETH 15m）

| 指标 | BTC:15m | ETH:15m |
| --- | --- | --- |
| 可开仓时段中：数据与闸门放行 | 56% | 52% |
| 其中被价差闸门 / Z 闸门转只减仓 | 21% / 20% | 26% / 18% |
| 正常时段占可开仓时段 | 26% | 29% |
| 正常时段至少一边有生效挂单 | 85% | 82% |
| 正常时段双边都有生效挂单 | 44% | 39% |

- 两个组合合计：每小时约 7 次成交、36 股；48% 的市场有成交（360 个中 172 个）；成交股数 / 挂出股数 = 0.19%。
- 期望：ev60 约 −1.8¢/股（比例队列下约 −1.0¢），45 h 结算盈亏 +$42。成交只涉及 172 个市场，结算残差主导、方差很大，**不能据此认为有正优势**。现有风控（单组合日亏 $25、日软/硬止损 $50/$100、周 $200）限定了最坏情况。
- 双边率达不到 100% 的主要原因：微价严重偏向一侧时，另一侧 fair−h 落后最优价超过 3 格；撤改单后 250 ms 生效延迟；剩余的深度守卫冷却。
- 挂单动作约每秒 1 次（每市场每秒最多 5 次的限速不变）。

## 6. 默认组合与录制周期

- 新的默认冷启动只用 observer 默认录制的周期（`POLYMARKET_OBSERVER_RECORDING_INTERVALS` 默认 `5m,15m`）：BTC/ETH 15m 全时段、BTC/ETH 5m 只做开盘前。
- **5m 开盘前要真正挂单**，需要 observer 提前发现下一场：`POLYMARKET_OBSERVER_UPDOWN_LOOKAHEAD_SECONDS>=300` 且 `UPDOWN_PER_PAIR_LIMIT>=2`。线上现在是 0/1，所以 5m 组合不会挂单；改了会多订阅约 8 个 token、多写约一倍的 books 行。在 observer 负载降下来之前不建议改。
- **启用 1h** 需要同时设置 `POLYMARKET_OBSERVER_UPDOWN_INTERVALS` 包含 `1h`（线上现在只有 `5m,15m`，1h 根本没被发现）和 `POLYMARKET_OBSERVER_RECORDING_INTERVALS=5m,15m,1h`，并先执行迁移（见 `pm_recording_scope_20261016.md`）。按 10/16 实测，每个 1h token 每秒 0.13–0.40 行，BTC/ETH 共 4 个 token，约每秒多 1 行、每天多约 10 万行。1h 用币安 K 线结算，代理结算要等官方结果 30 分钟。本 PR 不默认启用。

## 7. 官方结果迟到时回改账本

原来：回退到代理结算后，即使官方结果晚到且不同，账本也不会回改。

现在：

- 代理结算时，`Maker.effects` 预先算出 Up/Down/Tie 三种结果各自对现金、当日统计、组合统计、影子档、Brier/可靠性的增量，存入 `state.maker.estimates`。
- `RecordedFeed` 每次轮询都查询这些市场的 `official_outcome`。官方结果与代理不同时，`Maker.correct` 按差额回改：
  - 现金立即调整；
  - 结算当日的统计同步修正：`estimated_settlements` 减 1，新增 `settlement_corrections`；若当日已被清理，则记到今天；
  - 写 `settlement_correction` 事件和一条 `corrected=True` 的 `market_summary`。选市评分时，同一市场以更正后的那条为准。
- 结果相同则直接丢弃；3 天后仍无官方结果也丢弃。现金不足以扣回时，等下次轮询再试。

## 9. 复现

```bash
# 服务器上只读导出（示例：books 一个 6 小时块；其余见 maker_replay.EXPORT_SQL）
docker exec -e PGOPTIONS='-c default_transaction_read_only=on' quantdinger-db psql -U quantdinger -d quantdinger \
  -c "\copy (SELECT market_id,token_id,exchange_at,received_at,bids,asks FROM qd_polymarket_observer_books WHERE received_at>='2026-10-14 06:00+00' AND received_at<'2026-10-14 12:00+00') to stdout with csv" | gzip > books_2026101406.csv.gz
```

本地另放 `klines_BTCUSDT.csv.gz`、`klines_ETHUSDT.csv.gz`（币安公开 `/api/v3/klines?interval=1s`，两列 `open_ms,close`），然后：

```bash
python -m app.commands.polymarket_maker_replay --data DIR --cells BTC:15m,ETH:15m --source cold_start
python -m app.commands.polymarket_maker_replay --data DIR --set gap_max=.04 --set fair_tol=0 --set k_tox=3 --set open_max_behind_ticks=0 --set depth_pull_frac=.5 --set depth_pull_cooldown_ms=2000
```

单次全量（45 h × 2 个组合）约 3–4 分钟。
