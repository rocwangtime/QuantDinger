## 可复现的失效链

从 #68 commit 用 AST 提取原版 RateBalancer 离线执行，不连接任何行情源。24 个市场、48 个资产、每市场双资产同帧，10 秒窗口；同 shard 内市场 msg/s 为：

| shard | 六个市场 msg/s |
| --- | --- |
| 0 | 24 / 210 / 120 / 60 / 20 / 10 |
| 1 | 177 / 210 / 120 / 60 / 20 / 10 |
| 2 | 880 / 210 / 120 / 60 / 20 / 10 |
| 3 | 62 / 30 / 15 / 8 / 5 / 2 |

按市场连续突发发送。#68 只保留每个 shard 最近 2048 帧，样本中某市场没有出现便没有权重；用 total/len(samples) 放大尾部比例不会恢复前段丢失的资产。本实验有 12 个资产得到零速率。首次 EWMA 还乘以 `1-exp(-ln(2)*10/30)=0.2063`，初始估计成为 91.60/123.16/268.19/25.17，而非实际 444/597/1300/122。

原版完整 LPT 迁移后的估计为 119.21/118.98/150.33/119.60，实际为 **115/1933/120/295**；资产数 10/24/2/12。最热 shard 低估约 93.8%，同时看起来预测均衡。这复现了“错误低权重集中大量热资产”的机制，**不是对生产 30 资产/2120 的精确重建**。

- 主要偏差来自尾部样本不代表全窗口、冷资产当零；不是 total/len(samples) 量纲写反。
- 从零启动的 EWMA 进一步压低首轮总量。1 秒首轮仅保留真实速率的约 2.28%。
- #68 在 tick 时用当前 assignment 过滤旧样本，存在延迟归属隐患；上述实验固定 owner，已经复现偏差，故不需要归属变化也能触发。
- 样本构成恢复正常后原算法可能恢复；现有证据不能说明生产“此后不再搬迁”的唯一原因。

#60 把回调处理移到 worker；#61 恢复加权整市场迁移；#62 改差量换订阅。基线遗留计量仍在 worker，队列积压会量到消费率。#63 热资产拆分/合并曾撤回；#66 合并计数属于写队列，不能证明 WS 合并是否生效，且没有修正计量。此次不恢复这两套方案。

## 修复

1. 每个非 PONG 帧在接收回调中解析资产、按当前 owner 精确计数，先于 FIFO 接纳/拒收。多资产帧去重后平分一帧成本；不再依赖 2048 尾部样本或扩大比例，worker 不重复计数。计数内存按订阅资产数有界，不拿 Pipeline 锁，不做外部 I/O。
2. 每个资产首次测量直接使用完整窗口计数/秒数，之后保留原 EWMA。未见样本或未完成采样窗口时，不执行速率迁移。新增资产也进入冷启动保护；目录刷新保留现有 owner，不能绕过保护或迁移预算。
3. 整市场迁移单次最多 8 个资产（`POLYMARKET_OBSERVER_WS_REBALANCE_MAX_ASSETS`，默认 8，最小 2）。保留 YES/NO 同 shard、差量订阅和冷却。只选择改善负载的步骤，预算不足时等待下一周期。
4. 常规 hysteresis 保留；当前负载比仍 >=2 时允许较小但严格正向的后续改善，避免迁移预算截断后被 hysteresis 卡在 2:1 外。单个不可拆市场过热、或预算内没有改善步骤，仍可能无法达到 2:1；不作任意分布都能均衡的保证。
5. 新增 `ws_rate_unobserved_assets`、`ws_rebalance_max_assets` 状态指标；原 `ws_shard_loads` 为资产可归属帧成本 EWMA。坏 JSON、控制帧和非 owner 帧不计入资产权重，因此不是所有 wire 帧的无条件守恒指标。

## 测试与局限

先写回放/冷启动测试，在基线上确认失败，再实现修复。新增测试覆盖突发顺序、极不均匀市场、多资产成本守恒、冷启动、目录刷新、真实 manager 的 tick/冷却/迁移上限。真实 socket callback 回归在 Pipeline 锁阻塞时仍计入所有 110 帧，包括 FIFO 拒收的 100 帧。

回放初始估计修复后为精确 444/597/1300/122；对迁移后的每个 shard，独立按市场真实速率重新求和，断言估计误差 <20%，最终 max/min <2。manager 回放使用真实 tick 和实际迁移限制，不只检查预测布局。每一步都断言迁移资产数 <=8。该输入分两次分别迁移 8/4 个资产，最终负载 464/637/880/482，max/min≈1.897；逐分片估计误差为 0。合成流量验证不代表实盘性能或新鲜度改善。

为了消除采样偏差，本次选择回调 JSON 解析，worker 仍需解析盘口；这是明确的 CPU 开销取舍。离线 100000 条双资产小帧计量约 43 万帧/秒（单线程微基准，不是端到端吞吐保证）。超大帧、GIL、采样周期内构成变化、EWMA 对突变的滞后，以及不可拆热门市场仍需实际输入验证；不声称生产估计一定持续 <20%。
