## 交接正确性与计量边界

- 晋升不把拼装盘口误当成交易所新快照：继承原 snapshot floor 和每档真实时间戳。受控反例是快照 t=1000、bid 更新 t=1100，交接后收到 ask t=1050；若统一抬高 snapshot floor 到1100会丢掉合法 ask。新增行为测试同时验证该 ask 生效、同一 bid 的旧更新被拒。
- checkpoint 只保留每帧每资产的最终 hash（不重复保留同资产八行中间态），每资产最多2048条、hash最多128字符，并按订阅删旧资产；代际 resync 清空私有盘口。2倍回放最热组约850帧/s，窗口约2.4s，覆盖本次约1.1s主源静默；超过窗口或缺少共同水印时保守回退REST。status 的 book_checkpoint_charged_bytes 纳入有界内存预算，晋升释放私有梯子，不留下第三份活盘口。
- 同时刻比较完整盘口及 hash；热备落后但共同水印相符时保留已经更近的主源合流梯子，并让原有逐档去重/时间闸门挡住重放；热备领先时发布其已拼装基线。无快照、缺 hash/时间、盘口不等或无共同水印，均保留原恢复路径。完整盘口不证明成交历史完整，相关项仍仅告警。
- ready 继续表示可接替的物理供应资格，baseline_verified/need_book_assets 单独记录盘口资格，避免因为上游暂缺快照而永远失去存活备份。新 ws_rollover_gaps 显式区分 startup/rollover；正常事件沿用同 token 口径，没有同 token 基线的新场事件才采用具名 scheduled_market_start 口径。
