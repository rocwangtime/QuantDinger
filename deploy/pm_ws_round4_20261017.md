## 验收结果与范围

本轮完成备用连接预热后切换、首次快速重连与后续指数退避、冷热盘口分组新鲜度，以及外部常驻 ss 采样和日志轮转。能证明的是本地切换与恢复规则、监控期限和隔离行为；**没有线上运行新 observer，不能宣称 slow consumer/lost 已消失，也没有证明唯一根因。**

### 连接轮换

- `ws_rotation.py` 中的 ShadowBooks 仅维护当前订阅资产的盘口与时间戳，不缓存原始流，不把备用连接的成交重复送入持久化。
- 每次最多一个备用连接，原连接在预热期间继续发布。所有资产都必须收到完整快照；仅有 delta、成交或缺失 exchange timestamp 不能就绪。备用盘口每个资产的时间戳均须不落后于原连接最后发布的时间。
- 原连接继续更新时推进备用连接的最低时间戳门槛；原连接断开并清空 live books/metadata 后，门槛仍保留，不能因比较对象消失而接纳落后快照。
- 备用连接断开、准备超时、队列溢出/resync、交付缺口或积压时不切换。排队与等待发布锁后的实际消息年龄都检查，超过 1 秒不能发布。原连接健康时保留原盘口。
- 订阅变更先取消预热，再变更所有权。发现同步、tick、取消和切换由 lifecycle lock 串行；盘口与完整时间信息在 Pipeline lock 内发布，且持有 inbox lock，防止溢出打断两腿的发布。
- 切换后原代际被标记 retired/invalidate 并唤醒退出；原 worker 的清理及旧 on_open/on_message/on_error/on_close 不能覆盖新盘口、流量计数、连接状态或 slow consumer 计数。同一 state 发生普通重连时也检查 inbox 身份。
- 默认 `WS_ROTATE_SECONDS=2100`，shard 再错开 10 秒；0 关闭按年龄轮换。准备期限默认 30 秒，失败等待 30 秒后再准备；成功后至少等待 60 秒。退场线程数量有上限，不能因 teardown 卡住无限堆积备用订阅。
- 另有保守的数据塌陷保护：连接至少运行 60 秒，有繁忙流量基线，PONG 新鲜且未连续欠应答，非 PONG 消息字节连续 5 秒低于基线 5% 才准备轮换。基线最低 16384 B/s，调度采样空档打断连续安静计数，冷门静默和 PONG 本身不会触发。它是异常检测启发式，不能将其命中直接解释为服务端故障。

独立 supervisor 每约 0.2 秒 tick，使恢复和准备轮换不必等市场发现、retention 或状态 SQL。现有文本心跳线程保持独立。真正网络连接和锁被阻塞时仍可能延迟，因此该周期是调度目标，不是严格的端到端恢复 SLA。

### 重连

第一次失败不额外等待；连续短命失败的基础等待为 `0, 1, 2, 4, 8, 16, 32, 64, 120…` 秒，close 路径乘 0.8–1.2 抖动并封顶 120 秒。连接健康存活至少 60 秒后重置到首次失败档，下一次立即恢复，紧接着再次失败就退避，避免多放行一次快速重试。备用失败只取消预热，不计为原连接重连。

“快速”消除了原有约 5 秒的固定等待及市场主循环依赖；仍包含 supervisor 调度、旧 worker 退出、握手及快照到达时间。定向测试分别验证初始连接和长连接失败后的首次恢复，并检查后续退避与上限。

### 盘口新鲜度

`book_freshness_by_activity` 按订阅 token 横截面统计 `hot/cold/unmeasured`，每个 token 一次，避免消息量加权掩盖冷门盘口。阈值复用 `WS_HOT_GROUP_MSG_PER_S`（默认 100），按市场/系列组的实测 msg/s 分类；无可用组速率归 unmeasured。

每组报告订阅总数、具有可用 exchange timestamp 的数量、missing 数，以及 exchange age、receipt age、arrival lag 的 P95。缺盘口、缺时间戳或未来 exchange timestamp 不当成 0ms；没有测量值时返回 null。冷热拆分是解释信息，冷门静默本身不等于连接停流；全局旧指标和现有盘口使用规则保持不变。分组速率沿用健康窗口的最近观测值，不声称在中断期间仍是即时估计。

## 外部常驻采样与期限

`p34_monitor.py` 默认 `--duration 0`，直到停止；observer 慢通道和 TCP 快通道各自运行。快通道在 observer 的网络命名空间执行 `ss -tminp`，约每秒一次，每十轮读网络计数器。每次 SSH 的本地截止是 **49 秒**，远端 `timeout -k 1 47`，50 秒节拍再次连接；慢通道截止 40 秒。超时杀本地整个进程组并回收，父进程提前退出但后代持有 stdout 时也不等待 EOF。SSH 会话轮转有约数秒空档，不能称为连续抓包。

stdout 以非阻塞 pipe 有界读取。每个数据/heartbeat 文件默认最多 4 MiB、4 个备份，四路文件合计约 80 MiB 上限（不含 stdout 重定向文件）；即使单次 write 大于文件上限也分段轮转。heartbeat 记录 scheduled/start/end/timeout/missed/done 及 elapsed_seconds。旧进程的 56 秒冒烟原文保留在 `monitor_smoke/`，可见一次 46.255 秒正常会话、下一次在总预算约 6 秒截止，且 64 KiB 分段轮转生效；不能把这次总预算截止解释为远端网络故障。

本次接续又启动了无总时限的只读采样：

```sh
backend_api_python/.venv/bin/python deploy/p34_monitor.py \
  --duration 0 --output /tmp/pm-round4-resident
```

采样宿主在本地执行环境，远端仅运行短命只读命令，没有安装服务、定时器或上传部署文件。截至 02:25:09 UTC 的 `resident_capture/` 静态截取含 5 个完成的 TCP 会话（46.135–46.491 秒）和 3 个慢通道会话（3.695–4.076 秒），全部 returncode=0，无 timeout；它是该常驻进程的静态截取，运行日志继续写入 `/tmp/pm-round4-resident/`。应用改动未上线，采样看到的是原线上版本。任何本地宿主冻结、进程被停或环境回收仍会中断采样；常驻模式和日志轮转不能提供跨宿主冻结的保障。

## 历史断连对照

下表时间全部为 **2026-10-16 UTC**；北京时间/SGT 为次日加 8 小时。原始事件来自第 3 轮保留的 `monitor_smoke/observer.log.gz`，本轮索引为 `historical_lifecycle.jsonl`，精选对照在 `historical_comparison.json`。

| UTC | shard | 原始证据 | close 至 reconnect 调用 |
| --- | --- | --- | --- |
| 18:40:29.634133 | 3 | 关闭帧 `03 f5`，`slow consumer: send buffer full` | 4.634 秒 |
| 19:03:10.594599 | 3 | 同一明确的 slow consumer 关闭帧 | 7.021 秒 |
| 23:42:05.367759 | 0 | `Connection to remote host was lost.` | 7.367 秒 |
| 23:42:07.837201 | 1 | 同样 lost；与 shard 0 相隔 2.469442 秒 | 3.896 秒 |

这些是 close 到 reconnect **开始调用**的间隔，不是恢复盘口耗时。旧日志的 close 行均为 `code=None slow_consumer=False`，但前两次相邻原始关闭帧明确包含 1013（`03 f5`）和 slow consumer 原因；不能被旧 close 行的 False 误导。23:42 的 lost 则没有关闭帧及服务端原因，不能擅自补成 1013。

18:40 从 18:05:59 左右的一组初始连接算约 34.5 分钟；旧握手日志缺 shard 标记，时间只可近似。19:03 距 shard 3 的 18:42:20.784 重连调用约 20 分 49.8 秒，实际存活还略短。因此这些记录**不支持统一的 35 分钟连接寿命**；默认年龄轮换未必赶得上这两次故障。数据塌陷保护也只有在符合其流量/PONG 前提时才有机会提前准备，不保证覆盖突发关闭。

23:42 两个 shard 近同时 lost，提示共同路径/远端事件是待核查方向，但也可能有本机共享资源的瞬时问题。该时刻没有逐秒 ss 或 transport 历史，不能排除或确认丢包、远端重启、窗口耗尽、GIL/调度停顿。18:40、19:03 同样缺少关闭前 ss；第 3 轮 18:42 的小 Recv-Q 证据不能移用到这些时刻。

另外保留了 **2026-10-17 01:11:01 UTC shard 1 lost** 的内部传输历史（`production_lifecycle.txt`）：前 60 个样本中 59 个有 socket 字段，`tcp_pending_bytes` 全部 0，`rcv_wnd` 约 1.065–1.580 MB，采样间隔最大约 1.003 秒；最近 PONG 年龄约 0.514 秒。此窗口不支持持续的本机接收队列堵满或长时间心跳失联。最后错误回调样本已无 socket 字段，未知值不能用 0 替代；它也不能证明其他时刻无亚秒停顿或定位远端哪一层失败。

原长日志中混入两处相同 Docker 外层时间戳，原文未修改；`summarize.py` 只在派生解析时删除这两个完全相同的时间戳 token，并将次数与 token 写入对照 JSON，未修补或猜测其他字段。运行该脚本可重建历史精选及上述 transport 范围。
