# Polymarket 纸面做市 v3 · 币安现货 WebSocket 参考价 — 2026-10-16

基于 `feat/pm-maker-v3-20261016`（`5c125c1`）。目的：把 v3 毒性项里的现货年龄从 REST 的 0–5 s 降到亚秒级，让 15m/1h 开盘后重新可报。
只用币安公开行情（无凭证、无钱包、不签名、不下单、不碰 `PAPER_AUTO`）。开关默认关闭，关闭时行为与 v3 完全一致。未合并、未部署。

## 开关与参数

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `POLYMARKET_OBSERVER_SPOT_WS_ENABLED` | `false` | 打开后 observer 的参考价改为"WS 优先、REST 兜底"的组合源；REST 轮询照常运行 |
| `POLYMARKET_OBSERVER_SPOT_WS_FRESH_MS` | `1000`（100–10000） | WS 值的年龄不超过该值才使用，否则用 REST |
| `POLYMARKET_OBSERVER_SPOT_WS_AGGTRADE` | `true` | 同时订阅 aggTrade，只用来统计"交易所事件时间 → 本地接收"的时延，不参与定价 |
| `POLYMARKET_PAPER_MAKER_SPOT_STALE_MS` | `6000`（不变） | **开 WS 时建议改为 `1000`**；默认值仍按 REST 5 s 节奏保守设置 |

前提：`POLYMARKET_OBSERVER_UPDOWN_ENABLED=true`（参考价线程只在 Up/Down 观察开启时启动）。订阅的币种取 `POLYMARKET_OBSERVER_UPDOWN_ASSETS`。

## 行为

- **数据**：一条组合流连接 `wss://stream.binance.com:9443/stream?streams=<asset>usdt@bookTicker/...`（加 aggTrade 时一并订阅），价格 = (最优买 + 最优卖) / 2。只靠 URL 订阅，连接上从不发送任何帧。收不到任何帧就失败的连接（如 451 地区限制）会切到 `wss://data-stream.binance.vision/stream`。
- **回调**：接收回调只做 JSON 解析和加锁写内存字典（单帧约 2 µs；4 个币种实测约 300–360 帧/秒）。
- **年龄**：bookTicker 只在变化时推送。同一条连接仍在出帧、且该币种在本连接内 10 s 内更新过时，它的确认时间取连接最近一帧的接收时间（没推送就是没变）。重连后旧连接收到的价格不享受这一延长。
- **组合源选择**：WS 年龄 ≤ `FRESH_MS` 用 WS；否则用 REST；REST 也不可用时，WS 值在 REST 自身的有效期（3 × `REFERENCE_CACHE_SECONDS` = 15 s）内仍返回；再旧则 `unavailable`。返回字段在原有 `price/source/observed_at` 外多一个 `age_ms`。maker 只接受比已有观测更新的值，所以切换来源不会让价格倒退。
- **重连**：后台监督线程每 0.5 s 检查一次。断线后指数退避 1, 2, 4 … 60 s（×0.5–1.5 抖动）；稳定推流 ≥ 60 s 后断开（包括错过轮换时服务器的 24 h 强制断开）退避清零、约 1 s 后重连同一主机；连接存活但 10 s 无帧视为死连接，主动关闭重连；连接满 23.5 h 主动轮换，立即重连同一主机，间隙内由 REST 兜底。
- **时钟校准**：开 aggTrade 时，监督线程每 10 分钟调用 3 次公开接口 `/api/v3/time`（api.binance.com，失败换 data-api.binance.vision），取往返最短的一次估计"币安服务器 − 本地"偏差，时延分位数按此校正。精度约为往返不对称的一半。
- **写库**：`qd_polymarket_observer_samples.reference_source` 新增两个取值 `stream.binance.com`、`data-stream.binance.vision`（长度符合 `VARCHAR(40)`）。无新增表、无迁移。
- **结算代理**：`maker.RecordedFeed.outcome` 的 SQL 与 `backtest.proxy` 现在接受全部四个币安来源（`updown.BINANCE_SOURCES`，`backtest.BINANCE_SOURCES` 与之保持一致，有单测校验）。
- **maker**：`observe_spot` 的样本只按时间截断（保留 max(180 s, σ_short 窗口 + 10 s)），去掉"最多 400 个"。原上限在 4 Hz 下只覆盖 100 s，15m/5m 开盘 100 s 后才首次处理的市场会因开盘价 TWAP 窗口无覆盖而 `strike_unknown`（已写回归单测）。4 Hz 时每币种约 720 个样本，账户状态 JSON 相应变大（4 个币种约 100 KB）。其余默认值不变。

## 状态指标

observer 状态（每 10 s 写入 `qd_polymarket_observer_status`，接口 `GET /api/polymarket/observer/status`）在组合源开启时新增：

| 键 | 含义 |
| --- | --- |
| `spot_ws_state` | `streaming` / `connected` / `connecting` / `backoff` / `rotating` / `stopped` |
| `spot_ws_host`、`spot_ws_error` | 当前主机、最近错误 |
| `spot_ws_frames`、`spot_ws_frame_age_ms` | 累计帧数、距最近一帧 |
| `spot_ws_connects`、`spot_ws_reconnects`、`spot_ws_rotations` | 连接、非计划重连、计划轮换次数 |
| `spot_ws_age_ms` | 各币种距自身最近一次 bookTicker 更新（诊断用，不是对外年龄） |
| `spot_ws_lag_ms` | 最近 2000 笔 aggTrade 的"接收 − 事件时间"分位数 `p50/p90/p95/p99/max`，`clock_corrected` 表示是否已按时钟偏差校正 |
| `spot_ws_clock_offset_ms`、`spot_ws_clock_rtt_ms` | 币安服务器 − 本地时钟的估计值及其探测往返 |
| `spot_served` | 组合源按 `ws` / `rest` / `ws_stale` / `unavailable` 的累计返回次数 |

```sql
SELECT updated_at, status->'spot_ws_state', status->'spot_ws_lag_ms', status->'spot_ws_clock_offset_ms',
       status->'spot_ws_clock_rtt_ms', status->'spot_served'
FROM qd_polymarket_observer_status;
```

## 预期现货年龄

| | REST（现状） | WS（本分支） |
| --- | --- | --- |
| maker 看到的年龄 | 0–5 s 轮询 + HTTP 往返，平均约 2.5–2.8 s | 本机实测 p50 32 ms、p95 146 ms、最大 363 ms（4 币种，120 s，4 Hz 轮询） |
| Z 的有效延迟 `LATENCY_EFF_S + 年龄` | 0.3 + ~2.8 ≈ 3.1 s | 0.3 + ~0.05 ≈ 0.35 s |

Z ∝ √L，同一时刻的 Z 约降到原来的 1/3（单测按 √(0.4/2.8) 断言）。本机 120 s 实测：组合源 1888 次全部走 WS，maker 在 `SPOT_STALE_MS=1000` 下 0 次 `spot_stale`。

## 如何测量 `POLYMARKET_PAPER_MAKER_LATENCY_EFF_S`

v3 策略文档的定义：L = 行情延迟 p90 + 处理 + 撤单往返 p90 − 150 ms（平台吃单延迟）− 30 ms（最快吃单者反应）。maker 已把"接收到决策"的现货年龄单独加进 Z，所以这里的"处理"不再计轮询等待。

1. 部署主机先确认 NTP 同步（`sntp time.apple.com` 或 `chronyc tracking`）。本机测试时本地时钟慢约 180 ms，未校正的时延 p50 甚至是负数。
2. 打开 `SPOT_WS_ENABLED` 与 `SPOT_WS_AGGTRADE`，运行 ≥ 1 小时并覆盖美股开盘等活跃时段；每隔几分钟读一次上面的 SQL（每次读数约代表最近 3 分钟），确认 `clock_corrected=true`，记录 `spot_ws_lag_ms.p90`，取各次读数的高位（例如最大值）作为"行情延迟 p90"。
3. 在同一主机测 Polymarket 撤单往返（公开、无凭证）：

   ```bash
   python -c "import time,requests;s=requests.Session();s.get('https://clob.polymarket.com/time');x=sorted((lambda t:(s.get('https://clob.polymarket.com/time'),(time.perf_counter()-t)*1000)[1])(time.perf_counter()) for _ in range(50));print('p50',round(x[25]),'p90',round(x[45]))"
   ```

   这个值也是 `POLYMARKET_PAPER_MAKER_CANCEL_LATENCY_MS` / `PLACE_LATENCY_MS` 的依据（文档要求取实测 REST 往返 p90）。
4. `LATENCY_EFF_S = (行情延迟 p90 + 撤单往返 p90 − 180) / 1000`，向上取到 0.05 s，且不低于现行默认 0.30（实测更低时也先保留 0.30，等影子 markout 校准后再下调）。

本机（开发 Mac，非部署主机）2026-10-16 实测供参考：时钟偏差 +141～183 ms（探测往返约 129 ms）；校正后 aggTrade 时延 p50 68–202 ms、p95 0.23–2.0 s，三次运行间波动很大，说明这台机器的网络不适合作为依据；Polymarket `/time` 往返 p50 250 ms、p90 330 ms。按第 4 步，本机会得到 0.35–1.6 s，必须以部署主机的数据为准。

## 注意与已知限制

- **4σ 跳价护栏**：采样从 5 s 变成 250 ms 后，`JUMP_SIGMA=4` 在肥尾下触发更频繁。本机 120 s 内 SOL、XRP 各触发 2 次（每次整币种撤单冷却 3 s），BTC/ETH 为 0。上线后看日报 `skip_reasons` / 阶段分布里的 `coin_jump` 占比，过高再考虑调 `JUMP_SIGMA` 或按更长间隔判跳，本分支未改。
- **时延没有进入实时定价**：WS 时延抖动（本机 p95 最高 2 s）不会自动加到 Z 里，Z 只用静态 `LATENCY_EFF_S` + 年龄。若部署主机抖动也大，后续可把实时 p90 时延加入有效延迟。
- 开 WS 后若 WS 断开，组合源回退到 REST（年龄 0–5 s）。在 `SPOT_STALE_MS=1000` 下 maker 会转入平静期全撤，TWAP 窗口内的缺口（> 2 × `SPOT_STALE_MS`）会让该市场 `strike_unknown`，都属于保守方向。
- 样本表的 `reference_observed_at` 是本地接收时间（REST 现状亦然），本地时钟偏差会直接平移结算代理取样的边界，部署主机必须保持 NTP 同步。
- 结算代理与 maker 的 SQL 改动和 `claude/magical-austin-a97023`（录制范围分支）改的是同一行 `RecordedFeed.outcome` SQL，合并时会有一处文本冲突：在对方新 SQL 的 `reference_source IN (...)` 里补上两个 WS 来源即可。
