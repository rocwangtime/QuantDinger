# HK Agent decision scoring and daily reports (P0 item 5)

The existing Agent runner timestamps validated decisions in `result.decision_at`.
Celery Beat dispatches `quantdinger.tasks.hk_decision_scoring` every 60 seconds to
`maintenance`. This finite, quote-only job is separate from scheduler fast-decision
capacity and protection. It never calls a model, enables authorization, opens a
trade context, or submits orders. A PostgreSQL advisory lock excludes overlapping
jobs; bounded batches recover across restarts. Deployments must run the existing
Celery worker and Beat roles to collect outcomes.

Migration `20261012_agent_scoring.sql` adds scores, daily reports and risk events.
The normal migration command applies it before services start. Existing task/run
and order engines remain authoritative; SIMULATE execution gates are unchanged.

## Scores

Non-preview HK decisions in both `plan_only` and `paper_auto` produce one score per
symbol and horizon: 5 minutes, 30 minutes, session close and next session close.
Inputs come from persisted decision evidence/configuration, not later task edits.
The decision reference price is the price supplied to the model, with its quote
timestamp retained. Existing fast-path runs can use their persisted latency decision timestamp.
Legacy runs without a reliable decision timestamp and
model-free protection runs are excluded. The XHKG exchange calendar handles
weekends, holidays and shortened sessions.

Prices use **unadjusted** historical Futu `K_1M` closes, fetched for the target day
only. Intraday horizons round up to the first completed minute end (less than 60
seconds); session close requires the exact calendar close minute. Jobs allow 90
seconds for completed bars to become available. Lunch, suspension, unavailable
history and provider failures keep outcomes null and retry after 10 minutes;
no later session or current quote is substituted. `checked_at` distinguishes a
missing observation from work that has not yet been checked. Outcomes retain the
source and bar timestamp. Historical horizon prices are immutable once scored.

BUY/HOLD predict an increase; REDUCE/EXIT predict a decrease; WAIT is excluded
from the direction-hit denominator. A flat price is a miss. Raw price return and
directional return are both recorded. Hypothetical gross PnL uses frozen snapshot
cash, exposure, target weights, position ownership, order caps and whole lots.
HOLD uses owned whole lots, WAIT uses zero quantity, and absent lot size means
unknown PnL. Broker snapshot lot size is retained; configured lot size is a fallback.
These quantities are evaluation assumptions, **not executable order permissions**:
post-decision broker limits, authorizations and execution checks remain mandatory.
Hypothetical sell PnL measures avoided loss/gain relative to holding the shares.

Actual cumulative fill quantity and volume-weighted average fill price come from
run-linked intents. Positive side-adjusted slippage means an adverse fill versus
the decision price. Late partial/final reconciliation refreshes fill/slippage
fields without changing historical marks or adding duplicate quantities.

## Daily reports and API

Reports are generated by the same scheduled job after **17:00 Asia/Hong_Kong**
for that HK local day. Missing older reports recover on restart. Next-close scores,
late fills and risk events refresh their originating day's report. Counts include
triggered failed/expired runs but exclude previews and deterministic protection
from Agent decision counts. Per-task and per-symbol reports include decisions,
trigger counts, hit denominators, raw/directional average return by horizon,
hypothetical PnL, fill/slippage coverage, risk events and nearest-rank latency
P50/P95. Task equity change includes only the first/last recorded valid samples;
it is not presented as a complete trading-session return.

Risk events are written atomically with the existing protection state transition
for stop-loss symbols, daily-loss and drawdown latches. Repeated observations of a
latched condition do not duplicate events; explicit manual reset preserves history.
Historical transitions before this migration cannot be reconstructed.

Authenticated, owner-scoped, database-only endpoints:

- `GET /api/agent-automations/{task_id}/daily-report?day=YYYY-MM-DD` returns
  `{generated_at, report}`; both are null until a report is generated.
- `GET /api/agent-automations/runs/{run_id}/scores` returns persisted inputs,
  due times, checked times and nullable outcomes for the owner's run.

No frontend change is required; these endpoints support JSON review/export.
OpenAPI is regenerated with `backend_api_python/scripts/export_openapi.py`.

## Limits and validation

Per-decision PnLs overlap in time and cannot be treated as portfolio profit.
Fees, taxes, dividends, corporate actions and financing are excluded. Whole-lot
PnL assumptions do not imply broker acceptance or profitable trading. Missing
bars remain explicit; hit rates use only observed directional samples.

Tests use the backend `.venv`, only local PostgreSQL **18** and the disposable
`qd_automation_test` database, and stub all model/OpenD interfaces. They cover
calendar horizons, whole lots, pending data, idempotent recovery, late cumulative
fills, risk-event persistence and HTTP authentication/ownership. Real OpenD
history availability and multi-session behavior remain deployment acceptance work.

Local validation (2026-10-12): **184 selected tests passed**, including scoring,
Agent unit/PG integration, performance, research, run acceptance, latency/fast-slot,
Futu contracts and release gates. The shared DB fixture verifies PostgreSQL 18 and
restricts the DSN to local `qd_automation_test`; all broker/model interfaces were
stubbed. Ruff across app/scripts/tests, requirements lock, backend structure,
documentation and whitespace checks passed. OpenAPI export applied the new
migration successfully to that local test database. Two existing exchange-calendar
NumPy deprecation warnings remain. No server DSN, OpenD, deployment, push or merge
was used; frontend is unchanged.
